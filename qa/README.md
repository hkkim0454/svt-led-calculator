# QA 도구 — 시각 회귀 촬영

이 폴더는 **검사 도구**다. 제품(`src/`)은 이 폴더를 읽지 않고, `npm test` 도 이 폴더를
직접 돌리지 않는다. 여기 있는 것을 바꿔도 화면은 한 픽셀도 달라지지 않는다.

## 왜 있나

PHASE 7-c 에서 같은 코드인데 **촬영 순서만 바꾸면 그림이 달라지는** 일이 있었다.

원인은 LED 하단 높이(`#baseHeight`)였다.

- 이 값은 방 옵션이 아니라 **계산기 전역 입력**이다(기본 1,000mm).
- 화면을 다시 그릴 때마다 `clampBaseHeight()` 가 `벽 높이 − LED 실제 높이` 를 넘으면 값을
  **내린다**. 천장 3.0m 방에서 2,160mm 배열이면 상한이 840mm 라 1,000 → 840 이 된다.
- 그리고 **다시 올라오지 않는다.** 나중에 천장 6m 방으로 가도 840 그대로다.

그래서 천장 낮은 방을 먼저 본 촬영본은 LED 가 160mm 낮게 찍혔다(화면상 중심 2.08m → 1.92m).

**제품은 정상이다.** 사용자가 고른 설치 높이를 방을 바꿔도 유지하는 것은 맞고, 벽을 넘지
않게 자르는 것도 맞다. 잘못한 쪽은 촬영 도구였다 — 컷마다 이 값을 정해 주지 않고 앞 컷이
남긴 값을 그대로 썼다.

## 약속

> **한 컷의 그림은 그 컷의 명세만으로 정해진다.**
> 앞에서 무엇을 찍었는지, 몇 번째로 찍는지, 새로고침을 했는지와 무관하다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `capture-state.js` | 정규 상태 계약(순수 계산). 명세를 빈 곳 없이 채우고, 단계 순서를 정하고, 어긋남을 찾고, 지문을 만든다. DOM·브라우저를 모른다 |
| `capture-cases.js` | 찍을 컷 목록(고정 자료). 동결된 다섯 공간 + 레거시 네 공간 |
| `capture.mjs` | 실제 촬영기(Playwright). 위 계약대로 화면을 세우고 찍는다 |

`tests/capture-state.test.js` 가 앞의 두 파일과 촬영기의 **소스 계약**을 검사한다. 브라우저가
필요한 증명(순서를 바꿔도 같은 픽셀)은 아래 명령으로 직접 돌린다.

## 쓰는 법

먼저 정적 서버를 띄운다.

```
python3 -m http.server 5180 --directory src
```

그다음 촬영한다.

```
node qa/capture.mjs --port 5180 --out /tmp/list.json                      # 목록 순서
node qa/capture.mjs --port 5180 --order reverse --out /tmp/rev.json       # 뒤집어서
node qa/capture.mjs --port 5180 --order shuffle --seed 20260919 --out /tmp/s1.json
node qa/capture.mjs --port 5180 --fresh-page --out /tmp/fresh.json        # 컷마다 새 페이지
node qa/capture.mjs --port 5180 --only training-interior --out /tmp/one.json
```

어떤 순서로 돌려도 컷별 해시가 같아야 한다. 다르면 회귀이거나, 촬영 도구가 또 무언가를
정해 주지 않고 있는 것이다.

Playwright 는 **저장소 의존성이 아니다**(빌드리스 유지). 개발 기계에 설치된 것을 빌려 쓰고,
못 찾으면 `QA_PLAYWRIGHT` 로 경로를 알려 주면 된다. 브라우저 실행 파일은 `QA_CHROME` 으로
바꿀 수 있다.

## 컷 하나를 세우는 순서

순서 자체가 계약이다(`CAPTURE_STEPS`).

1. `resetBrowserState` — 저장값을 지우고 앱을 처음 상태로 띄운다
2. `enterViewer` — 창 크기·화면 배율을 정하고 3D 작업영역으로 들어간다
3. `selectModel` — LED 제품을 고른다
4. `roomType` — 공간 타입
5. `dimensions` — 가로·높이·깊이
6. `ledState` — LED 크기·배열·**하단 높이**
7. `design` — 공간 디자인
8. `roomOptions` — 방별 옵션
9. `accessories` — 서 있는 사람 등 소품
10. `view` — 시점
11. `settle` — 장면이 멈출 때까지
12. `assertState` — 요청한 값과 실제 값이 같은지 확인
13. `capture` — 찍는다

치수를 LED 보다 먼저 두는 까닭은, 하단 높이의 상한이 `벽 높이 − LED 높이` 이기 때문이다.
순서를 바꾸면 나중에 값이 잘려 컷마다 다른 결과가 나온다.

## 멈춤 판정

시간을 기다리지 않고 **화면이 멈췄는지**를 직접 본다.

- 시점 전환이 끝났는가(`getView().animating === false`)
- 글꼴이 준비됐는가(`document.fonts.ready`)
- 그림이 **연속 세 프레임** 동안 그대로인가

세 프레임인 까닭: 조작기가 관성(`dampingFactor 0.08`)으로 몇 프레임 더 움직인다. 그리기
반복문은 움직임이 있을 때만 다시 그리므로, 세 프레임 연속으로 같은 그림이면 더 바뀔 것이
없다는 뜻이다. 기계가 느려도 결과가 같다.

## 기억해 둘 것

컷 목록에서 **천장이 낮은 칸**(`training-compact-interior`, 8 × 3.0 × 7m)을 빼지 말 것.
이 컷이 하단 높이를 자르는 유일한 칸이라, 빠지면 이번에 고친 문제가 촬영 목록에서 사라져
회귀가 생겨도 드러나지 않는다.
